SEO and AI discovery
====================
Current primary domain: https://kunalkaushik.vercel.app/
Future custom domain: https://kunalsk.com/

The build generates metadata, entity/project structured data, robots.txt, sitemap.xml, and AI-readable files from your content. The production page is prerendered. Run npm run build; SEO checks run automatically after the build.

Domain setup and indexing:
1. Buy kunalsk.com and attach it under Vercel > project > Settings > Domains. Apply the exact DNS records Vercel provides at your registrar. Confirm Vercel shows a valid configuration and the homepage, CSS, images and videos all load on the custom domain.
2. Only after it works, change siteUrl in src/content/site.ts to https://kunalsk.com and deploy. All metadata, sitemap and plain-text URLs update together.
3. Then configure a permanent redirect from kunalkaushik.vercel.app to kunalsk.com in Vercel. Do not redirect CSS/assets to a domain that is not connected yet.
4. Verify your active domain in Google Search Console. A Domain property uses a DNS TXT verification record. Submit /sitemap.xml on that domain and request indexing for the homepage. The preserved HTML verification token may belong to the older property.
5. Add the active site to Bing Webmaster Tools, or import the verified Search Console property.
6. Set LinkedIn and GitHub website links to the active primary URL. Monitor branded-name impressions and indexing in Search Console.

/ai/, /llms.txt and /llms-full.txt stay available. AI-readable files are a convenience, not a guarantee of search rankings or AI citations. Coming-soon projects are excluded from completed-work structured data.

References:
https://developers.google.com/search/docs/appearance/ai-features
https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls

The premature custom-domain redirect was removed because it redirected production CSS requests to a domain that did not resolve. Keep the Vercel domain serving all assets until the custom domain is verified.
